Honest scope notes
  * This ran on PostgreSQL 16, not Supabase's PostgreSQL 17, with a small emulation of Supabase's roles, auth.uid(),
    auth.role() and default privileges (tests/00_supabase_shim.sql). It proves the SQL logic, constraints, privileges,
    RLS and rollback. It does NOT prove behaviour through PostgREST / GoTrue / real JWTs.
  * Production's real schema may differ from the baseline. The migration depends only on auth.users, public.bmn_admins,
    public.is_bmn_owner() and the three Supabase roles, and refuses to run if any of those is missing.
  * Bugs found by this suite during development, all fixed before this run:
      - migration bug: pg_get_serial_sequence() raised an error on a table with no "id" column (the failed migration
        rolled back completely, leaving nothing half-applied);
      - test defects: a baseline trigger needs auth.role() (shim fixed); two assertions read a row inside the same
        statement that modified it (split into two checks); one test called a test-only helper as a restricted role.
